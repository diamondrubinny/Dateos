# התקנת Dateos, צעד אחר צעד

[English](INSTALL.md) · **עברית**

המדריך הזה לוקח אתכם משרת ריק לאפליקציית היכרויות פעילה לקהילה שלכם, עם השם, הצבעים וצוות המודרציה
שלכם. בפעם הראשונה כדאי לתכנן כשעה, ורובה המתנה ל-DNS ולבנייה הראשונה. לא צריך להיות מפתחים: אם
אתם יודעים להתחבר לשרת ב-SSH ולהדביק פקודות, תצליחו.

> ⚖️ מי שמפעיל שרת של Dateos הוא המפעיל (בדיני פרטיות: בעל השליטה במאגר) של המידע של חברי הקהילה.
> קראו את שלב 8 לפני שמזמינים מישהו, ובקשו מעורך/ת דין לבדוק את המסמכים המשפטיים לפי הדין במדינה
> שלכם. שום דבר במאגר הזה אינו הצהרה על עמידה בדרישות החוק.

כבר מכירים Docker? [SELF_HOSTING.md](SELF_HOSTING.md) הוא גרסת העזר הקצרה (באנגלית).

## מה יהיה לכם בסוף

| כתובת                       | מה זה                                                   |
| --------------------------- | ------------------------------------------------------- |
| `https://example.org`       | האפליקציה לחברי הקהילה (עובדת בכל דפדפן בטלפון ובמחשב)  |
| `https://admin.example.org` | לוח המודרציה, בשבילכם ובשביל המודרטורים                 |
| `https://api.example.org`   | השרת שהאפליקציה מדברת איתו (חברי הקהילה לא פותחים אותו) |

בכל המדריך, החליפו את `example.org` בדומיין שלכם.

## לפני שמתחילים

- [ ] **שרת**: Linux ‏(x86-64), לפחות 2 מעבדים וירטואליים, 4GB זיכרון ו-40GB דיסק. מתאים כל שרת
      וירטואלי של ספק ענן. הוסיפו 4GB זיכרון אם רוצים את הבינה המלאכותית המקומית (רשות).
- [ ] **דומיין** בשליטתכם, שאפשר להוסיף לו רשומות DNS (גם תת-דומיין כמו `dating.example.org` מתאים).
- [ ] **שירות לשליחת מיילים** (SMTP): חברי הקהילה נכנסים בקישור שנשלח במייל, ולכן זה חובה. כל ספק
      מיילים טרנזקציוניים, או שרת הדואר של הארגון שלכם.
- [ ] כשעה פנויה וכתובת מייל שלכם (אתם תהיו המנהלים הראשונים).

התוכנה חינמית (רישיון MIT). משלמים רק על השרת, הדומיין ושירות המיילים.

## שלב 1: הכנת השרת

התחברו לשרת ב-SSH והתקינו **Docker Engine עם התוסף Compose**, וגם `git` ו-`openssl`, לפי ההוראות
הרשמיות של Docker להפצת ה-Linux שלכם 📘 (<https://docs.docker.com/engine/install/>). **לא** צריך
Node.js על השרת.

✅ **בדיקה:** שתי הפקודות מדפיסות מספר גרסה.

```bash
docker --version
docker compose version
```

## שלב 2: הפניית הדומיין לשרת

בהגדרות ה-DNS של הדומיין, צרו שלוש רשומות שמצביעות על כתובת ה-IP הציבורית של השרת (`A` ל-IPv4,
וגם `AAAA` אם לשרת יש IPv6):

| שם                  | סוג      | ערך                |
| ------------------- | -------- | ------------------ |
| `example.org`       | A (AAAA) | כתובת ה-IP של השרת |
| `admin.example.org` | A (AAAA) | כתובת ה-IP של השרת |
| `api.example.org`   | A (AAAA) | כתובת ה-IP של השרת |

בחומת האש של הספק, פתחו את הפורטים **80** ו-**443** ‏(TCP) ואת **443** ‏(UDP). השאירו את כל השאר
סגור: מסד הנתונים, Redis, אחסון הקבצים וסורק הווירוסים מאזינים רק בתוך השרת.

שינויי DNS יכולים לקחת בין כמה דקות לכמה שעות.

✅ **בדיקה:** `ping admin.example.org` (מהמחשב שלכם) מראה את כתובת ה-IP של השרת.

## שלב 3: הורדת Dateos ויצירת ההגדרות

```bash
sudo mkdir -p /opt/dateos && sudo chown "$USER" /opt/dateos
git clone https://github.com/diamondrubinny/Dateos.git /opt/dateos
cd /opt/dateos
./install.sh --domain example.org
```

סקריפט ההתקנה:

- יוצר סיסמאות אקראיות חזקות למסד הנתונים, ל-Redis, לאחסון הקבצים ולהתחברות, וכותב אותן לקובץ
  `.env` (רק אתם יכולים לקרוא אותו, והוא אף פעם לא נשמר ב-git);
- מגדיר את שלוש הכתובות לפי הדומיין שלכם;
- מדפיס **קוד הגדרה חד-פעמי**. העתיקו אותו למקום בטוח: תצטרכו אותו בשלב 6. (הוא שמור גם ב-`.env`
  בשם `SETUP_TOKEN`.)

✅ **בדיקה:** `ls -l .env` מראה `-rw-------` (רק אתם יכולים לקרוא).

> שמרו עותק של `.env` במקום בטוח מחוץ לשרת. בלעדיו אי אפשר לשחזר גיבויים.

## שלב 4: חיבור שירות המיילים

פתחו את `.env` (למשל `nano .env`) ומלאו את הפרטים שספק המיילים נותן לכם:

```bash
SMTP_HOST=smtp.your-provider.example
SMTP_PORT=587
SMTP_USER=your-username
SMTP_PASSWORD=your-password
SMTP_FROM="Your Community <no-reply@example.org>"
```

כדי שמיילי ההתחברות לא יגיעו לספאם, הגדירו SPF ו-DKIM לדומיין לפי ההסבר של ספק המיילים 📘.

## שלב 5: הפעלה

כדי לחסוך הקלדה, צרו קיצור (הריצו פעם אחת בכל התחברות SSH, או הוסיפו ל-`~/.bashrc`):

```bash
alias dc='docker compose -f /opt/dateos/infra/docker-compose.yml --env-file /opt/dateos/.env --profile app --profile full'
```

ואז בנו והפעילו:

```bash
cd /opt/dateos
dc up -d --build
```

ההפעלה הראשונה לוקחת כמה דקות: בונים את התוכנות, סורק הווירוסים מוריד חתימות, ושרת האינטרנט מבקש
תעודות HTTPS מ-Let's Encrypt (זה עובד רק אחרי שה-DNS משלב 2 מצביע על השרת).

✅ **בדיקה:**

```bash
dc ps                                   # כל השירותים "running" או "healthy"
curl https://api.example.org/ready      # {"status":"ready", ...} וכל בדיקה "up"
```

אחר כך פתחו את `https://example.org` בדפדפן: אמור להופיע מסך הפתיחה.

## שלב 6: תפיסת השרת והתאמה אישית

1. פתחו את `https://admin.example.org`, הזינו את המייל שלכם ולחצו על קישור ההתחברות שתקבלו.
2. הזינו את **קוד ההגדרה** משלב 3. עכשיו אתם המנהלים הראשונים, והקוד מפסיק לעבוד.
3. הגדירו **אימות דו-שלבי**: סרקו את קוד ה-QR באפליקציית אימות (Aegis, ‏2FAS, ‏Google Authenticator,
   ‏1Password…) והזינו את הקוד. זה חובה לכל הצוות.
4. מתגו את הקהילה: שם, משפט תיאור, צבע (הלוח לא מקבל צבעים שיהיה קשה לקרוא), שפת ברירת מחדל, לוגו,
   ו**שם המפעיל ומייל ליצירת קשר** (מופיעים בעמודים המשפטיים ובהצהרת הנגישות).

✅ **בדיקה:** רעננו את `https://example.org`: השם, הלוגו והצבע שלכם מופיעים, במצב בהיר ובמצב כהה.

## שלב 7: הוספת מודרטורים

כל מודרטור/ית נכנס/ת קודם פעם אחת ל-`https://admin.example.org` (כדי שהחשבון ייווצר). אחר כך, על
השרת:

```bash
dc exec api node dist/cli/staff.js grant moderator@example.org moderator
dc exec api node dist/cli/staff.js list
```

התפקידים הם `moderator` (דיווחים, אזהרות, השעיות, אימות תמונות) ו-`admin` (הכול, כולל חסימות
ויומן הפעולות). איך עובדים דיווחים והחלטות: [ADMIN.md](ADMIN.md).

## תוספות (רשות)

### בינה מלאכותית מקומית (התאמה חכמה יותר ופותחי שיחה)

כברירת מחדל Dateos לא משתמשת בשום מודל בינה מלאכותית: ההתאמה מבוססת על דמיון בין טקסטים, ופותחי
השיחה הם תבניות מוכנות בכל שפה. כדי להשתמש במודל קטן שרץ **על השרת שלכם** (שום מידע לא יוצא ממנו),
צריך עוד כ-4GB זיכרון:

```bash
dc --profile ai up -d ollama
dc --profile ai exec ollama ollama pull paraphrase-multilingual   # להתאמה
dc --profile ai exec ollama ollama pull qwen2.5:1.5b              # לפותחי שיחה ולרעיונות לתיאור
```

ואז הגדירו ב-`.env`:

```bash
EMBEDDINGS_PROVIDER=ollama
ICEBREAKERS_PROVIDER=ollama
```

והפעילו מחדש עם פרופיל ה-AI: ‏`dc --profile ai up -d --force-recreate api worker` (מעכשיו הוסיפו
`--profile ai` לקיצור). מודלים קטנים טובים באנגלית וחלשים יותר בעברית ובערבית; התבניות נשארות
כגיבוי. פרטים ואפשרות הענן: [AI.md](AI.md).

### התראות פוש

כבויות כברירת מחדל. צריך בנייה משלכם של האפליקציה (Expo EAS) ו-`PUSH_PROVIDER=expo` ב-`.env`.
ההתראות לא כוללות שמות או תוכן הודעות, אבל הן עוברות דרך Expo, ‏Apple ו-Google, ולכן יש לציין זאת
במדיניות הפרטיות ⚖️. ראו [SELF_HOSTING.md](SELF_HOSTING.md#push-notifications-optional).

### אפליקציות ב-App Store וב-Google Play

לא חובה: אפליקציית הדפדפן עובדת בטלפונים ואפשר להוסיף אותה למסך הבית. לאפליקציות בחנויות, בנו את
`apps/mobile` עם Expo בחשבונות המפתחים שלכם 📘. ראו [SELF_HOSTING.md](SELF_HOSTING.md#mobile-apps).

### הגבלת לוח הניהול למשרד או ל-VPN

בקובץ `infra/web/Caddyfile`, בבלוק `admin.{$DOMAIN}`, בטלו את ההערה בשתי שורות `@outside`, שימו את
טווח כתובות ה-IP שלכם במקום `203.0.113.0/24`, והריצו `dc up -d --build web`.

## יום-יום

| משימה               | פקודה                                             |
| ------------------- | ------------------------------------------------- |
| עדכון לגרסה האחרונה | `cd /opt/dateos && git pull && dc up -d --build`  |
| מה רץ עכשיו         | `dc ps`                                           |
| קריאת לוגים         | `dc logs -f api` (או `worker`, ‏`web`, ‏`clamav`) |
| החלת שינוי ב-`.env` | `dc up -d --force-recreate api worker`            |
| עצירת הכול          | `dc stop` (המידע נשמר)                            |
| הפעלה מחדש          | `dc up -d`                                        |

עדכוני מסד הנתונים רצים אוטומטית כשהגרסה החדשה עולה. קראו את [CHANGELOG.md](../CHANGELOG.md) לפני
עדכון.

### גיבויים

`scripts/backup.sh` שומר את מסד הנתונים ואת כל התמונות וההודעות הקוליות, מוצפנים בסיסמה, ומוחק עותקים
מקומיים ישנים מ-14 יום. מגדירים פעם אחת:

```bash
head -c 32 /dev/urandom | base64 | sudo tee /root/.dateos-backup-key >/dev/null
sudo chmod 600 /root/.dateos-backup-key
sudo crontab -e
# הוסיפו את השורה הזו: גיבוי בכל לילה ב-03:00
0 3 * * * cd /opt/dateos && BACKUP_PASSPHRASE_FILE=/root/.dateos-backup-key ./scripts/backup.sh
```

העתיקו את הקבצים מ-`/opt/dateos/backups/` למקום אחר (שרת אחר או שירות אחסון), ושמרו את הסיסמה ואת
`.env` בנפרד מהם. מדי פעם נסו שחזור למסד נתונים נפרד:

```bash
RESTORE_DATABASE=dateos_check BACKUP_PASSPHRASE_FILE=/root/.dateos-backup-key \
  ./scripts/restore.sh backups/dateos-db-<time>.dump.enc
```

## שאלות ותשובות

**כמה זה עולה?**
התוכנה חינמית ובקוד פתוח (רישיון MIT), בלי מסלול בתשלום. העלויות שלכם הן השרת, הדומיין ושירות
המיילים, והן תלויות בספקים שתבחרו.

**מה צריך לדעת כדי להפעיל את זה?**
להתחבר לשרת ב-SSH, להדביק פקודות ולערוך קובץ טקסט. לקהילה שגדלה, כדאי שמישהו שמרגיש בנוח עם שרתי
Linux יטפל בעדכונים ובגיבויים.

**אפשר לנסות קודם על המחשב שלי?**
כן, עם Node.js ו-pnpm מותקנים. הריצו `./install.sh` בלי `--domain`, הפעילו את השירותים עם הפרופילים
`full` ו-`dev`, ואז `pnpm install` ו-`pnpm dev`, כמו שמוסבר ב-[README](../README.md#quick-start). מיילי
ההתחברות מגיעים לתיבת דואר מקומית (Mailpit, ‏<http://localhost:8025>) ולא לכתובות אמיתיות.

**באילו שפות האפליקציה?**
עברית, אנגלית, ערבית ורוסית, עם תצוגה מימין לשמאל בעברית ובערבית. כל חבר/ת קהילה בוחר/ת שפה
באפליקציה; את שפת ברירת המחדל בוחרים בלוח הניהול.

**איפה נשמר המידע של חברי הקהילה?**
רק על השרת שלכם: מסד הנתונים והתמונות וההודעות הקוליות נמצאים שם ב-volumes של Docker. שום דבר לא
נשלח ליוצרי Dateos. מיילים עוברים דרך ספק המיילים שלכם, והתראות פוש (אם הפעלתם) דרך Expo, ‏Apple
ו-Google. הרשימה המלאה ב-[PRIVACY.md](PRIVACY.md).

**צריך סיסמה כדי להיכנס?**
לא. נכנסים בקישור שנשלח במייל, כך שאין סיסמאות שיכולות לדלוף. אפשר להוסיף כניסה עם Google ו-Apple
דרך ההגדרות `GOOGLE_*` ו-`APPLE_*` ב-`.env`.

**הבינה המלאכותית חובה? היא שולחת מידע לחברה כלשהי?**
לא ולא. כברירת מחדל אין שום מודל. הבינה המלאכותית המקומית (רשות) רצה על השרת שלכם. שירות AI בענן
משמש רק אם הגדרתם אחד וכל חבר/ת קהילה הסכימו.

**כמה חברים שרת אחד מחזיק?**
בבדיקת עומס עם 5,000 חברים על מכונה אחת עם 4 מעבדים וירטואליים, מציאת התאמות לקחה 62ms ושליחת
הודעה 16ms ‏(אחוזון 95); ראו [PERFORMANCE.md](PERFORMANCE.md). לקהילה גדולה יותר, קחו שרת גדול יותר
ועקבו אחרי הזיכרון והדיסק בכלי הניטור של הספק.

**אפשר להשתמש בשם ובלוגו שלנו?**
כן, זו בדיוק המטרה: שם, משפט תיאור, צבע, לוגו ושפת ברירת מחדל מוגדרים בלוח הניהול. הרישיון מבקש רק
להשאיר את הודעת זכויות היוצרים של MIT בקוד המקור.

**מותר להפעיל אפליקציית היכרויות לקהילה שלנו?**
זה תלוי במדינה ובקהל, ולכן שאלו עורך/ת דין ⚖️. במאגר יש טיוטות של מדיניות פרטיות, תנאי שימוש, מדיניות
עוגיות והצהרת נגישות, וגם מדריך פרטיות שמפרט כל סוג מידע שנשמר, אבל הם נקודת פתיחה ולא ייעוץ משפטי.
בישראל בדקו גם את חובות חוק הגנת הפרטיות ותיקון 13 (רישום מאגר, ממונה הגנת פרטיות, אבטחת מידע) ⚖️.

**צריך באנר עוגיות?**
האפליקציה משתמשת רק בעוגיות הנחוצות להתחברות, בלי מעקב ובלי אנליטיקס, ולכן אין בה באנר הסכמה; העמוד
"פרטיות ועוגיות" שלה מסביר זאת. אם תוסיפו כלי משלכם, בדקו זאת עם עורך/ת הדין ⚖️.

**איך עוברים לשרת חדש?**
עשו גיבוי בשרת הישן, העתיקו לשרת החדש את קבצי הגיבוי, את `.env` ואת `infra/data/seaweedfs/s3.json`,
בצעו שם את שלבים 1, 2 ו-5 (לא את `install.sh`, שייצור סיסמאות חדשות), שחזרו עם
`scripts/restore.sh <db-backup> <files-backup>` ועדכנו את ה-DNS.

**אפשר להחליף דומיין אחר כך?**
כן. ב-`.env` שנו את `DOMAIN`, ‏`PUBLIC_API_URL`, ‏`CORS_ORIGINS` ו-`SMTP_FROM` לשם החדש, הוסיפו את
רשומות ה-DNS החדשות והריצו `dc up -d --build` (אפליקציית הדפדפן נבנית מחדש עם הכתובת החדשה).

**איך מוחקים הכול?**
`dc down -v` עוצר את Dateos ו**מוחק לצמיתות את כל המידע**, כולל כל חשבונות החברים. אם ייתכן שתצטרכו
אותו, עשו ושמרו גיבוי קודם, והודיעו לחברי הקהילה מראש ⚖️.
